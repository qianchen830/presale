| 字段 | 控件 | 规则 |
|------|------|------|

## 三、数据模型

`app_state` 新增 key `schedules[]`（写库沿用 `moduleOp` 机制，含 `createdAt/updatedAt/consultant(创建人)/软删标记`，与既有模块一致）：

```jsonc
{
  "id": "id_msXXXXXXXX_XXXXXX",        // 沿用现有 genId 规则（moduleOp 兜底 Date.now()）
  "type": "项目",                        // 项目|会议|培训|休假|其他（存中文，同 buyMode 口径）
  "appId": "id_msvqgloh_h2eb2u",        // 关联售前申请 id；type=项目 时必填
  "oppNo": "OPP202603260789",           // 冗余溯源
  "customer": "重庆瑞通精工…", "projectName": "瑞通PLM项目",
  "sales": "湛小东", "department": "客户成功业务一部",   // 带出快照
  "consultant": "刘云飞",                // **被安排的顾问**（⚠️ moduleOp 默认会写创建人，此处必须显式传目标顾问）
  "scheduleDate": "2026-04-06",          // 避开既有代码对 record.consultant 的"归属=本人"语义
  "startTime": "09:00", "endTime": "10:00",
  "note": "",
  "createdBy": "系统管理员", "createdAt": "…", "updatedAt": "…"
}
```

设计说明：
- 带出字段做**快照**，申请单后续修改不影响已排事项展示；`appId/oppNo` 保留溯源。
- 字段名用 `scheduleDate` 避免与既有模块可能的 `date` 语义冲突；`consultant` 语义=被安排人（创建人在 `createdBy`，模块归属校验对 schedules 特殊处理，见 4.2）。
- 数据量：全员日均个位数条目，年增量万条以内，对 `/api/state` 全量下发与导出（gzip 数据块）影响可控，P4 实测确认。

## 四、后端改动（server.js，仅 3 处）

### 4.1 白名单（L1055）

### 4.2 moduleOp 增加 schedules 业务分支（复用 allocations 校验模式）

- **权限**：create/update/delete 前置校验 `session.role === 'admin'`（与 requireAdmin 同一判定源），非 admin 返回「仅管理员可操作排程」。
- **必填校验**：type ∈ 枚举；consultant、scheduleDate、startTime、endTime 必填；`startTime < endTime`（HH:mm 字符串比较）；type=项目 时 appId 必填；consultant 必须存在于员工表（防脏数据打错名）。
- **冲突检测**（create 与 update 都执行，update 排除自身）：

```js
const conflict = (state.schedules || []).find(s =>
  !s._deleted && String(s.id) !== String(record.id)
  && s.consultant === record.consultant
  && s.scheduleDate === record.scheduleDate
  && s.startTime < record.endTime && record.startTime < s.endTime);
if (conflict) return { error: `时间冲突：【${s.consultant}】当天已有【${s.type}${s.projectName?'·'+s.projectName:''} ${s.startTime}-${s.endTime}】与此时间段重叠` };
```

- **归属**：schedules 不走 `checkModuleOwnership` 的"consultant=本人"语义（admin 代排程，consultant 是被安排人），单独按角色判定。
- **软删**：沿用既有删除机制；所有读取/冲突扫描均过滤已删除记录。

### 4.3 无新路由

- 读：`/api/state` 已含 schedules（全量下发机制不变）。
- 增删改：既有 `POST/PUT/DELETE /api/modules/:module` 直通，前端零适配。

## 十、风险与注意事项

1. **`consultant` 语义**：moduleOp 默认把 `record.consultant` 写成创建人，且 update 分支强制回填 `arr[idx].consultant`——schedules 必须显式传目标顾问并**跳过**该回填逻辑，否则被安排人会被覆盖为 admin（实现时最易踩的坑）。
2. 单文件体量：index.html 6141 行，新增约 1000 行；函数名统一 `sc*/rb*` 前缀防冲突。
3. 姓名软关联：员工表存在脏数据（position="王娟"）；顾问下拉数据源为员工表 name 去重，保存时服务端校验在册。
4. 导出文件（gzip 数据块）会随 schedules 增长，P4 实测确认体积可控。
